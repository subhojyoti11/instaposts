Caption
Forget the word "Metaverse" for a moment. The real, unglamorous problem behind connected 3D worlds is that a model built in one engine cannot simply be opened in another. Export an avatar from one tool and the geometry usually survives, but the materials, the rig, the animation setup, and the physics often do not. There is no shared document format for 3D the way HTML is a shared document format for the web. Two efforts are trying to become that format. glTF, from the Khronos Group, is a compact standard designed for delivery: shipping one finished model to a viewer or a web page efficiently. It is excellent at that and weak at describing a whole editable scene. OpenUSD, which came out of Pixar, aims higher. A USD scene is a stack of layers, each layer a set of non-destructive changes to the world. Studios reference shared assets rather than copying them, so a fix to a character propagates everywhere it appears, and different departments can override parts of a scene without stepping on each other. Any tool that speaks USD reads the same stack and gets the same result. The fight between them is really a fight about the container, not the headset. Whether a 3D avatar can walk from Unreal to Unity to a spatial OS depends entirely on whether those engines all read and write the same scene format faithfully, and that is an adoption problem more than a technical one. The blocker to a connected 3D web was never the graphics hardware. It is the same thing that blocked the early web: getting everyone to agree on one file format their tools can open. #openusd #gltf #3dpipeline #spatialcomputing #ravenextechnologies
