Three Ways to
Find a Route.

🔁
BRUTE FORCE
Try everything
Goal
Check every possible path between two points.
Focus
Explores combinations exhaustively, no prioritization.
Result
Guaranteed correct, computationally impossible at scale.
📊
DIJKSTRA
Cheapest first
Goal
Always expand the cheapest known path so far.
Focus
A priority queue explores outward by lowest cost first.
Result
Optimal and efficient, but explores every direction equally.
🎯
A*
Cheapest + closest
Goal
Prioritize paths that are both cheap and headed toward the goal.
Focus
Adds a distance estimate to the goal into the priority.
Result
Same optimal route, dramatically fewer roads examined.

07 / 07

Quick
Reference.

Dijkstra's algorithm
A shortest-path search that always expands the lowest-cost unexplored node next.
A* search
Dijkstra's algorithm plus a heuristic estimate that biases the search toward the goal.
Heuristic
An estimate of remaining cost to the goal, used to guide search without guaranteeing exactness alone.
Priority queue
A data structure that always returns the lowest-cost item first, the engine behind both algorithms.

Caption
When your maps app finds the fastest route across a city in under a second, it isn't testing every possible path between two points. It's running a queue that only ever explores the cheapest option next. Checking literally every combination of roads between two points is mathematically hopeless at city scale, the number of possible routes explodes far beyond anything that could be evaluated one by one, even on fast hardware. A naive search that just expands outward in every direction has no sense of where the destination even is, wasting real computation exploring roads that are obviously heading the wrong way entirely. Dijkstra's algorithm, published in 1959, solves the first problem by always expanding whichever known path is cheapest so far, using a priority queue instead of a plain list, guaranteeing the shortest route is found without ever needing to check every combination. It's provably optimal, but it still explores in every direction fairly equally, with no bias toward the actual destination. The A* algorithm, a 1968 extension, adds exactly that bias. Alongside the real cost of a path so far, it adds a heuristic, typically a straight-line distance estimate to the goal, into the priority calculation. That single addition steers the search toward the destination without sacrificing the guarantee of finding the truly shortest route, and in practice it examines a dramatically smaller slice of the road network to arrive at the identical answer Dijkstra's algorithm would. The map never actually "sees" the destination in any meaningful sense. It only ever compares which unexplored road segment currently looks cheapest to try next, repeatedly, until the goal happens to be the node it pulls off the queue. Live traffic constantly reweights those road costs in real time, changing which path is genuinely cheapest minute to minute. The exact same priority-queue search also routes packets across computer networks and finds paths for characters in video games, the algorithm doesn't know or care that it's roads. #pathfinding #algorithms #computerscience #dijkstra #ravenextechnologies
