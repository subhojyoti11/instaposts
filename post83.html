The Data
Collection Tax.

Standard ML
Ship user data to a central server, train one big model on all of it. Simple, and a massive liability.
The risk
Every upload is a breach waiting to happen. Health records, keystrokes, and photos become a single high-value target.
The regulation
GDPR and HIPAA increasingly restrict moving personal data across borders. Centralizing it is now a legal problem, not just a technical one.

The model needs patterns in the data, not the data itself. That distinction is the entire premise of federated learning.

04 / 07

Federated
Averaging.

# FedAvg, McMahan et al. 2016 def federated_round(global_model, devices): local_updates = [] for device in sample(devices, k=100): local_model = copy(global_model) local_model.train(device.private_data) local_updates.append(local_model.weights) # average the weights, not the data global_model.weights = mean(local_updates) return global_model

The server never sees a single training example. It only ever averages weight updates from thousands of devices.

Central vs
Federated.

Centralized
Data moves

vs
Federated
Model moves
Only weight updates leave the device
Privacy exposure
Centralized: one breach exposes everyone. Federated: raw data never leaves the device in the first place.
Bandwidth
Federated sends small weight deltas each round instead of continuously uploading raw sensor and usage data.
The catch
Non-IID data: every device's data looks different. Averaging unevenly distributed updates can slow or skew convergence.

07 / 07

Quick
Reference.

Federated learning
Trains a shared model across many devices without ever moving their raw data to a central server.
FedAvg
Averages locally trained weight updates from a sample of devices each round to update the global model.
Non-IID data
Every device's local data distribution differs, which is the central hard problem in making federated learning converge well.
Secure aggregation
Cryptographically ensures the server can only see the average update, never any single device's contribution.

Caption
Every time your phone suggests the next word, a model somewhere got smarter. It just did not get smarter from your data leaving your device. Standard machine learning collects everything on a central server and trains one model on the pile. It works, and it is a liability by construction. Every upload is a breach waiting to happen, and regulations like GDPR now treat moving personal data across borders as a legal problem, not just an engineering one. Google faced this directly with Gboard. Predicting your next word requires learning from how a billion people actually type, but uploading raw keystrokes was never going to be acceptable. Federated learning inverts the pipeline. Instead of sending data to the model, you send the model to the data. Each round, a server samples a batch of devices and pushes them the current global model. Every device trains locally for a few steps using only its own private data, then sends back the updated weights, never the data that produced them. The server averages these updates across all sampled devices, a method called FedAvg, and the global model improves by one round. Repeat this thousands of times and you get a model trained on the collective experience of a billion phones, with no server ever holding a single training example. It is not free. Non-IID data is the central hard problem: your typing habits look nothing like your neighbor's, and averaging wildly different local updates can slow convergence or bias the model toward whoever happened to be sampled that round. Secure aggregation adds another layer, cryptographically ensuring the server only ever sees the combined average, never any individual device's contribution. This is already running quietly at scale. Gboard's next-word prediction, Apple's on-device Siri personalization, and hospital consortiums training shared diagnostic models without pooling patient records are all federated systems. The pattern generalizes anywhere data is too sensitive, too regulated, or too large to centralize, but still valuable enough to learn from collectively. #federatedlearning #privacyai #machinelearning #ondeviceml #differentialprivacy #ravenextechnologies
